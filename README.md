# EMBERGLASS GPU pipeline

Генерация ассетов на арендованной карте: **FLUX.2 klein** (концепт) → **TRELLIS.2**
(image → 3D). Пререндер спрайтов, отбор и постобработка — дома, на своей машине,
через `tools/assetgen/bake/` основного репозитория.

Один образ, один под, батч готовится заранее. GPU включён только когда считает.

## 1. Что проверено, а что было неверно в исходном плане

Всё ниже — замеры и обращения к источникам, а не предположения.

### Подтвердилось

| Утверждение | Статус |
| --- | --- |
| `microsoft/TRELLIS.2-4B` существует, MIT, image→3D с PBR, 512³–1536³ | да |
| TRELLIS.2 требует ≥24 ГБ VRAM, только Linux | да, A40 48GB подходит |
| `FLUX.2-klein` открыт, Apache 2.0, ComfyUI поддерживает нативно | да |
| A40 на Community Cloud ≈ $0.44/час | да |
| Остановленный под дороже работающего: $0.20 против $0.10 за ГБ/мес | да, Terminate — единственный разумный режим |

### Исправлено

**1. Dockerfile из инструкции был написан под TRELLIS первой версии.**
Там `torch 2.5.1`, `cubvh`, `diso`. TRELLIS.2 требует `torch 2.6.0` и других
расширений: `nvdiffrast`, `nvdiffrec`, `cumesh`, `o-voxel`, `flexgemm`.
Образ бы собрался и упал уже на оплачиваемой карте.

**2. `fetch_weights.sh` тянул половину FLUX.2.**
Klein нужны отдельный текстовый энкодер (Qwen3-8B) и **свой** `flux2-vae`;
со старым VAE от FLUX.1 цвета едут. Плюс диффузионная модель лежит в **gated**
репозитории — нужен `HF_TOKEN` и разово принятое соглашение.

**3. Берём `klein-base-9b-fp8`, а не `klein-9b-fp8`.**
Дистиллированный вариант требует `cfg = 1.0`, а при `cfg = 1.0` ComfyUI
пропускает безусловный проход, и **негативный промпт не действует вообще**.
Все промпты арт-библии построены на негативах. Базовый вариант работает на
`cfg 3.5–5.0`, 20–24 шага, Euler + Simple.

**4. flash-attn готовым колесом поставить нельзя, и сверка ABI из чеклиста
инструкции вводит в заблуждение.**

Замерено в контейнере:

```
torch 2.6.0+cu124   _GLIBCXX_USE_CXX11_ABI = False
libc10.so экспортирует  _ZN3c105ErrorC2ENS_14SourceLocationESs        <- старый ABI
оба колеса flash-attn 2.8.3/torch2.6 требуют
                        _ZN3c105ErrorC2ENS_14SourceLocation...__cxx11...  <- новый ABI
```

Колесо, помеченное `cxx11abiFALSE`, требует символ **нового** ABI — то есть
несовместимо с torch 2.6.0 независимо от пометки. Проверено и на torch с
cu124-индекса, и с PyPI: результат одинаковый. Поэтому проверять
`torch._C._GLIBCXX_USE_CXX11_ABI` бесполезно, единственный надёжный критерий —
фактический импорт.

Показательно, что `setup.sh` самого Microsoft просит `flash-attn==2.7.3`, а
колёс под cu12+torch2.6 в этом релизе нет вовсе — официальный путь тоже
компилирует из исходников.

**Решение:** по умолчанию `ATTN_BACKEND=xformers` (штатный запасной бэкенд,
документированный TRELLIS.2; проверено, что `xformers 0.0.29.post3` живёт с
torch 2.6.0+cu124). Кому нужна максимальная скорость — `WITH_FLASH_ATTN=1`
собирает из исходников. Это стоит времени **сборки**, а не GPU-времени.

**5. 3D идёт мимо ComfyUI.**
Враппер-ноды TRELLIS.2 существуют минимум в четырёх конкурирующих форках, без
документированных требований. Ставить на них самый тяжёлый этап — лишний риск.
ComfyUI остаётся только для 2D, где FLUX.2 поддержан нативно.

### Осталось нерешённым

- **UniRig вынесен в фазу 2.** Сейчас игра печёт технику, ей скелет не нужен:
  движение и отдача делаются сдвигом меша (GDD §3.3 фиксирует, что башни
  жёстко направлены по корпусу). Пехоте риг понадобится — тогда и добавим.
- **Схема нод FLUX.2 в ComfyUI не проверена живьём** — под ещё не поднимался.
  Именно поэтому граф не записан руками, а собирается кодом и валидируется
  против `/object_info`: `run_session.py doctor` покажет расхождение за секунду
  и на CPU, а не на оплаченной карте.

## 3. Сборка

Локально (WSL, контекст обязан лежать на ext4 — на `/mnt/c` IO очень медленный):

```bash
rsync -a --delete ./ ~/gpupipe/
cd ~/gpupipe && docker build -t ghcr.io/<owner>/emberglass-gpupipe:latest .
```

С компиляцией flash-attn (десятки минут, требует много ядер):

```bash
docker build --build-arg WITH_FLASH_ATTN=1 -t ghcr.io/<owner>/emberglass-gpupipe:flash .
```

GPU для сборки не нужен — компиляции хватает toolkit из базового образа.

## 4. Под

Template: образ из GHCR, Container Disk **120 GB**, Volume Disk **0**,
HTTP-порт **8188**, переменная `HF_TOKEN`. Community Cloud, не Secure.

Ритм сессии:

```
create pod
  ├─ ~10 мин  образ + веса                 ~$0.08
  ├─ doctor   проверка схемы и весов       секунды
  ├─ concepts батч                          минуты
  ├─ sheets   контактные листы              минуты
  ├─ rsync вниз
  └─ TERMINATE  (не Stop!)
── дома, бесплатно ──
  отбор по листам → Blender → bake_unit.py --mesh → verify_sheet.py
```

## 5. Команды

```bash
python /opt/pipe/run_session.py doctor
python /opt/pipe/run_session.py concepts --seeds 4
python /opt/pipe/run_session.py concepts --faction MRC --unit-class heavy_vehicle --seeds 6
python /opt/pipe/run_session.py sheets
python /opt/pipe/run_session.py mesh --pick picks.txt
```

Все этапы идемпотентны: существующие файлы пропускаются. Прерванный под
(Community Cloud) продолжается с того же места — это стоит минуты, а не сессию.

Забрать результат:

```bash
rsync -avz -e "ssh -p <port>" root@<ip>:/workspace/output/ ./out/
```

## 6. Промпты

`pipeline/prompts/units.json` — все 16 юнитов ростера (GDD §5.3, §5.4).

Промпты §11.2 GDD писались под SDXL — гребёнка ключевых слов под CLIP.
FLUX.2 klein кодирует текст Qwen3, который держит плотное связное описание
лучше, поэтому промпты переписаны в повествовательную форму. Семантика
сохранена: силуэт фракции, палитра с hex, класс, роль, конвенция света §3.4.
У каждого юнита проставлен `gdd_ref`, чтобы расхождение можно было отревьюить.

Шесть юнитов ростера в §11.2 отсутствовали и написаны с нуля
(`origin: authored`): `mrc_sapper`, `mrc_slugger`, `mrc_marksman`,
`kln_stoker`, `kln_arcpike`, `kln_bellows`.

## 7. Стыковка с основным репозиторием

На выходе — GLB. Дальше он идёт в уже существующий запекатель:

```bash
blender.exe --background --python tools/assetgen/bake/bake_unit.py -- \
    --mesh <asset>.glb --mesh-yaw-offset <0|90|180|270> \
    --mesh-length 1.0 --target-lightness 27 --name <unit_id>
uv run --with pillow python tools/assetgen/bake/verify_sheet.py <...>.json
```

Поправка `--mesh-yaw-offset` подбирается по факту: генераторы кладут «перед»
модели куда угодно. Проверяется не на глаз, а проекцией вектора на экранные
оси — см. `tools/assetgen/bake/README.md`.
